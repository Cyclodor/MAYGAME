# Интеграция системы логирования в игру

## ✅ Что было сделано

Система логирования и отладки автоматически интегрирована в игру и запускается при каждом запуске.

### Интеграция в `main.py`

1. **Автоматическая инициализация** при запуске игры
2. **Автоматическое обновление** в каждом кадре игрового цикла
3. **Автоматическое сохранение отчетов** при выходе из игры
4. **Обработка критических ошибок** с логированием

### Интеграция в `main_web.py`

Аналогичная интеграция для веб-версии игры.

## 🚀 Как это работает

### При запуске игры:

1. Система автоматически инициализируется
2. Создаются файлы логов в `debug/logs/`
3. Выводится сообщение о том, что система активна
4. Начинается сбор метрик и логирование

### Во время игры:

1. **Каждый кадр** система автоматически:
   - Обновляет метрики производительности (FPS, память)
   - Выполняет периодические проверки валидации
   - Запускает диагностику с заданными интервалами
   - Логирует события (если они логируются в коде)

2. **Автоматические проверки**:
   - Валидация состояния игры (каждые 5 секунд по умолчанию)
   - Диагностика проблем (каждые 10 секунд по умолчанию)
   - Проверка производительности (каждую секунду)

### При выходе из игры:

1. Автоматически сохраняются все отчеты:
   - Статистика логирования
   - Метрики производительности
   - История ошибок

## 📝 Использование в коде

Теперь вы можете использовать систему логирования в любом месте кода:

```python
from debug.system import get_logger, LogCategory

logger = get_logger()

# Логирование действий
logger.info(LogCategory.COMBAT, "Атака выполнена", {'damage': 10})
logger.error(LogCategory.SPELLS, "Ошибка применения заклинания", exception=e)

# Специализированные методы
logger.log_unit_action(unit, "move", {'from': (x1, y1), 'to': (x2, y2)})
logger.log_combat_action(attacker, defender, damage, is_ranged=False)
logger.log_spell_cast(spell, caster, target, success=True)
logger.log_ai_decision(unit, "attack", {'target': target.unit_type})
```

## 📊 Где найти логи

Все логи сохраняются в директории `debug/logs/`:

- `game_YYYYMMDD_HHMMSS.log` - основной лог всех событий
- `errors_YYYYMMDD_HHMMSS.log` - только ошибки
- `stats_YYYYMMDD_HHMMSS.json` - статистика логирования
- `metrics_YYYYMMDD_HHMMSS.json` - метрики производительности

## ⚙️ Настройка

Вы можете настроить систему через файл `debug/system/config.json`:

- Включить/выключить категории логирования
- Изменить уровни логирования
- Настроить интервалы проверок
- Изменить пороги предупреждений

## 🔧 Отключение системы

Если нужно временно отключить систему, можно:

1. Удалить или переименовать директорию `debug/system/`
2. Или установить `DEBUG_SYSTEM_ENABLED = False` в `main.py`

Система автоматически обработает отсутствие модулей и продолжит работу без логирования.

## 🐛 Устранение проблем

Если система не запускается:

1. Проверьте, что установлен `psutil`: `pip install psutil`
2. Проверьте, что директория `debug/system/` существует
3. Проверьте консоль на сообщения об ошибках
4. Система продолжит работу даже при ошибках инициализации
