## 1. Введение

### 1.1 Назначение документа
Документ описывает стратегию и подход к тестированию игры **Фэнтези Стратегия**, пошаговой 2D стратегии в фэнтези сеттинге. Цель тестирования — подтвердить соответствие системы требованиям, обеспечить стабильность и корректность работы основных игровых механик, боевой системы, заклинаний и интерфейса.

### 1.2 Объекты тестирования
- **Игровой движок:** Python, Pygame
- **Игровая логика:** Боевая система, система ходов, инициатива
- **Графика и анимации:** Отрисовка юнитов, анимации, эффекты заклинаний
- **Звук и музыка:** Звуковые эффекты, фоновая музыка
- **ИИ:** AIController, логика принятия решений
- **Интерфейс:** Меню, кнопки, тултипы, окна информации
- **Настройки:** Разрешение экрана, полноэкранный режим, громкость

## 2. Цели тестирования
- Проверить корректность боевой системы (атака, защита, урон, контратака).
- Убедиться, что система ходов и инициатива работают правильно.
- Проверить механику заклинаний (применение, перезарядка, эффекты).
- Подтвердить корректность работы ИИ противника.
- Оценить стабильность графики и анимаций.
- Проверить работу всех режимов игры (бой, креативный, редакторы).
- Проверить обработку пользовательского ввода (мышь, клавиатура).
- Оценить производительность на различных разрешениях экрана.

## 3. Область тестирования

- ✅ Запуск игры и главное меню

- ✅ ИИ противника (принятие решений, действия)

- ✅ Анимации и звуковые эффекты

## 4. Стратегия тестирования

| Тип | Детали |
|---|---|
| **Модульные тесты (Unit)** | Логика классов Unit, Spell, BattleManager, AIController (pytest, unittest) |
| **Интеграционные тесты** | Взаимодействие компонентов (Game ↔ BattleManager ↔ Unit) |
| **Функциональные тесты** | Ручная проверка игровых сценариев и механик |
| **Smoke-тесты** | Быстрая проверка работоспособности после сборки (запуск, меню, начало боя) |
| **Регрессионные тесты** | Проверка ранее исправленных багов |

## 5. Виды тестирования

### 5.1 Функциональные
- Запуск игры и навигация по меню
- Настройка боя (выбор рас для обеих команд)
- Выбор и перемещение юнитов
- Атака вражеских юнитов (ближний и дальний бой)
- Применение заклинаний героями
- Завершение хода и переход к следующему юниту
- Определение победителя
- Креативный режим (размещение/удаление юнитов)
- Редакторы (изменение характеристик юнитов и заклинаний)
- Настройки (разрешение, полноэкранный режим, звук)

### 5.2 Нефункциональные

| Вид | Цель |
|---|---|
| **Производительность** | FPS ≥ 60 на средних настройках, время отклика на действия < 100 мс |
| **Совместимость** | Работа на Windows 10/11, корректное отображение на разных разрешениях (800x600 - 1920x1080) |
| **Надёжность** | Стабильная работа без падений, корректная обработка некорректных действий пользователя |
| **Удобство использования** | Интуитивный интерфейс, понятные подсказки, визуальная обратная связь |
| **Графика** | Корректная отрисовка всех юнитов, анимаций, эффектов заклинаний |

## 7. Тестовые данные

- **Расы для тестирования:** Все доступные (human, undead, elf, demon, dwarf, shadow)
- **Юниты:** По одному представителю каждого типа из каждой расы
- **Герои:** Все классы героев (warrior, archer, mage) для каждой расы
- **Заклинания:** Все доступные заклинания для каждой расы
- **Сценарии боя:** Различные комбинации рас, различные позиции юнитов
- **Экстремальные случаи:** Юниты с максимальными/минимальными характеристиками, отряды с большим количеством юнитов

## 10. Оценка рисков

| Риск | Вероятность | Влияние | Митигирование |
|---|---|---|---|
| Падение игры при некорректных действиях | Средняя | Высокое | Обработка исключений, валидация входных данных, тестирование граничных случаев |
| Проблемы с производительностью на слабых ПК | Средняя | Среднее | Оптимизация рендеринга, настройки производительности, тестирование на различных конфигурациях |
| Некорректная работа ИИ | Средняя | Среднее | Тестирование различных сценариев, логирование решений ИИ, отладка |
| Ошибки в расчете урона/защиты | Низкая | Высокое | Модульное тестирование боевой логики, проверка формул расчета |
| Проблемы с сохранением настроек | Низкая | Низкое | Тестирование записи/чтения JSON файлов, проверка валидации данных |

## 12. Тестовые сценарии (примеры)

### TC-GAME-01: Запуск игры
**Предусловия:** Игра установлена  
**Шаги:**
1. Запустить BattleGame.exe или python main.py
2. Проверить отображение главного меню
3. Проверить наличие кнопок: "Новая игра", "Креативный режим", "Настройки"

**Ожидаемый результат:** Игра запускается, меню отображается корректно

---

### TC-BATTLE-01: Настройка боя
**Предусловия:** Игра запущена, главное меню открыто  
**Шаги:**
1. Нажать "Новая игра"
2. Выбрать расу для первого игрока (player1)
3. Выбрать расу для второго игрока (player2)
4. Проверить инициализацию юнитов

**Ожидаемый результат:** Юниты созданы, очередь ходов сформирована, бой начат

---

### TC-UNIT-01: Перемещение юнита
**Предусловия:** Бой начат, выбран активный юнит  
**Шаги:**
1. Выбрать юнит левой кнопкой мыши
2. Кликнуть на доступную клетку в пределах дальности хода
3. Проверить перемещение юнита

**Ожидаемый результат:** Юнит перемещен, move_points_left уменьшено

---

### TC-COMBAT-01: Атака врага
**Предусловия:** Бой начат, выбран активный юнит, враг в пределах досягаемости  
**Шаги:**
1. Выбрать свой юнит
2. Кликнуть на вражеского юнита
3. Проверить расчет урона
4. Проверить анимацию атаки
5. Проверить уменьшение здоровья цели

**Ожидаемый результат:** Урон нанесен корректно, анимация воспроизведена, здоровье уменьшено

---

### TC-SPELL-01: Применение заклинания
**Предусловия:** Бой начат, выбран герой с достаточной маной  
**Шаги:**
1. Выбрать героя
2. Нажать клавишу 1, 2 или 3 для выбора заклинания
3. Выбрать цель (союзник/враг)
4. Применить заклинание
5. Проверить эффект заклинания

**Ожидаемый результат:** Заклинание применено, эффект работает, мана уменьшена, перезарядка установлена

---

### TC-AI-01: Работа ИИ
**Предусловия:** Бой начат, одна из команд управляется ИИ  
**Шаги:**
1. Дождаться хода ИИ
2. Наблюдать за действиями ИИ
3. Проверить корректность решений (перемещение, атака, заклинания)

**Ожидаемый результат:** ИИ принимает разумные решения, выполняет действия корректно

---

### TC-VICTORY-01: Определение победителя
**Предусловия:** Бой в процессе  
**Шаги:**
1. Уничтожить всех юнитов одной из команд
2. Проверить определение победителя
3. Проверить отображение экрана победы/поражения

**Ожидаемый результат:** Победитель определен корректно, экран победы/поражения отображается
