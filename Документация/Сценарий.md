# Сценарии взаимодействия пользователя с программой

### 1. Запуск игры и главное меню

*   **Основной поток:**
    1. Пользователь запускает игру (BattleGame.exe или python main.py).
    2. Система инициализирует Pygame, загружает настройки из data/settings.json.
    3. Система отображает главное меню с кнопками: "Новая игра", "Креативный режим", "Настройки".
    4. Пользователь выбирает действие кликом мыши.
*   **Альтернативный поток (ESC для выхода):**
    1. Пользователь нажимает ESC в меню.
    2. Система закрывает игру.

---

### 2. Настройка боя

*   **Основной поток:**
    1. Пользователь нажимает "Новая игра" в главном меню.
    2. Система переходит в состояние 'battle_setup'.
    3. Пользователь выбирает расу для первого игрока (player1): 'human', 'undead', 'elf', 'demon', 'dwarf', 'shadow'.
    4. Система сохраняет выбор и предлагает выбрать расу для второго игрока (player2).
    5. Пользователь выбирает расу для второго игрока (не может совпадать с первой).
    6. Система инициализирует юнитов для обеих команд согласно выбранным расам.
    7. Система формирует очередь ходов на основе инициативы юнитов.
    8. Система переходит в состояние 'game' и начинает бой.
*   **Альтернативный поток (Настройка параметров):**
    1. Пользователь может настроить разрешение экрана и полноэкранный режим перед началом боя.
    2. Настройки сохраняются в data/settings.json.

---

### 3. Игровой процесс - Выбор и перемещение юнита

*   **Основной поток:**
    1. Система выделяет текущего активного юнита из очереди ходов (turn_queue).
    2. Пользователь кликает левой кнопкой мыши на клетку с другим юнитом своей команды.
    3. Система проверяет, что юнит принадлежит команде игрока и еще не ходил в этом раунде.
    4. Система выделяет выбранного юнита и отображает доступные клетки для перемещения (подсветка на основе speed и move_points_left).
    5. Пользователь кликает на доступную клетку.
    6. Система проверяет, что клетка свободна и находится в пределах дальности хода.
    7. Система перемещает юнита на выбранную клетку, уменьшает move_points_left.
    8. Система обновляет направление взгляда юнита (facing) в сторону движения.
*   **Альтернативный поток (Юнит уже ходил):**
    1. Система не позволяет выбрать юнита, у которого has_moved = True.
    2. Отображается визуальная индикация недоступности.

---

### 4. Игровой процесс - Атака

*   **Основной поток:**
    1. Пользователь выбирает свой юнит (левая кнопка мыши).
    2. Пользователь кликает на вражеского юнита в пределах дальности атаки (attack_range).
    3. Система проверяет, что цель является врагом (team != selected_unit.team).
    4. Система проверяет, что юнит еще не атаковал в этом раунде (has_attacked = False).
    5. Система рассчитывает урон на основе phys_attack/magic_attack атакующего и phys_defense/magic_defense защищающегося.
    6. Система применяет урон через метод take_damage().
    7. Система воспроизводит анимацию атаки и звук.
    8. Система проверяет возможность контратаки (если защищающийся еще не контратаковал).
    9. Система устанавливает has_attacked = True для атакующего.
*   **Альтернативный поток (Контратака):**
    1. Если защищающийся юнит еще не контратаковал (has_counterattacked = False).
    2. Система автоматически выполняет контратаку с уменьшенным уроном.
    3. Система устанавливает has_counterattacked = True для защищающегося.

---

### 5. Игровой процесс - Применение заклинаний

*   **Основной поток:**
    1. Пользователь выбирает героя (Hero) из своей команды.
    2. Система проверяет, что у героя есть заклинания (spells) и он не использовал заклинание в этом раунде (used_spell_this_round = False).
    3. Пользователь нажимает клавишу 1, 2 или 3 для выбора заклинания из списка.
    4. Система открывает книгу заклинаний (spellbook_open = True) или применяет заклинание напрямую.
    5. Пользователь выбирает заклинание из списка доступных.
    6. Система проверяет, что у героя достаточно маны (mana >= spell.mana_cost) и заклинание не на перезарядке (spell.current_cooldown == 0).
    7. Пользователь кликает на цель (союзник для 'ally', враг для 'enemy', любая клетка для 'area').
    8. Система проверяет дальность применения заклинания.
    9. Система применяет эффект заклинания (урон, лечение, бафф, дебафф).
    10. Система воспроизводит анимацию заклинания и звук.
    11. Система уменьшает ману героя, устанавливает перезарядку, помечает used_spell_this_round = True.
*   **Альтернативный поток (Недостаточно маны):**
    1. Система отображает сообщение о недостатке маны.
    2. Заклинание не применяется.
*   **Альтернативный поток (Отражение заклинания):**
    1. Если цель имеет magic_resist > 0 и заклинание является дебаффом.
    2. Система проверяет шанс отражения (равен проценту magic_resist).
    3. При успешном отражении заклинание применяется к кастеру вместо цели.

---

### 6. Игровой процесс - Завершение хода

*   **Основной поток:**
    1. Пользователь завершает действия с текущим юнитом (перемещение и/или атака выполнены, или пропуск хода).
    2. Система вызывает next_turn() из BattleManager.
    3. Система удаляет текущего юнита из очереди ходов (turn_queue.pop(0)).
    4. Если очередь пуста или достигнут разделитель раунда (_round_delimiter):
    5. Система увеличивает round_number на 1.
    6. Система сбрасывает флаги всех юнитов (has_moved, has_attacked, has_counterattacked).
    7. Система восстанавливает move_points_left = speed для всех юнитов.
    8. Система уменьшает длительность эффектов (curse_turns, attack_buff_turns и т.д.).
    9. Система восстанавливает ману героев на основе knowledge.
    10. Система формирует новую очередь ходов на основе инициативы.
    11. Система выбирает следующего юнита из очереди.
*   **Альтернативный поток (Проверка победы):**
    1. После каждого хода система проверяет, остались ли юниты у каждой команды.
    2. Если у одной из команд не осталось юнитов (health <= 0 для всех):
    3. Система устанавливает game_over = True и victory_state = 'victory' или 'defeat'.
    4. Система отображает экран победы/поражения.

---

### 7. Креативный режим

*   **Основной поток:**
    1. Пользователь выбирает "Креативный режим" в главном меню.
    2. Система переходит в состояние 'creative'.
    3. Пользователь выбирает расу из списка доступных.
    4. Пользователь выбирает тип юнита из списка доступных для выбранной расы.
    5. Пользователь кликает левой кнопкой мыши на свободную клетку поля.
    6. Система создает юнит выбранного типа и размещает его на клетке.
    7. Пользователь может размещать юнитов разных рас и типов.
*   **Альтернативный поток (Удаление юнита):**
    1. Пользователь кликает правой кнопкой мыши на юнита.
    2. Система удаляет юнит с поля.

---

### 8. Редактор юнитов

*   **Основной поток:**
    1. Пользователь выбирает "Редактор юнитов" из меню (если доступно).
    2. Система переходит в состояние 'unit_editor'.
    3. Пользователь выбирает тип юнита для редактирования.
    4. Система отображает текущие характеристики юнита: health, phys_attack, magic_attack, phys_defense, magic_defense, speed, initiative и другие.
    5. Пользователь изменяет значения характеристик.
    6. Система сохраняет изменения в data/unit_overrides.json.
    7. Изменения применяются при следующем создании юнита этого типа.

---

### 9. Редактор заклинаний

*   **Основной поток:**
    1. Пользователь выбирает "Редактор заклинаний" из меню (если доступно).
    2. Система переходит в состояние 'spell_editor'.
    3. Пользователь выбирает заклинание для редактирования.
    4. Система отображает параметры заклинания: name, damage, mana_cost, cooldown, target_type, duration, school.
    5. Пользователь изменяет значения параметров.
    6. Система сохраняет изменения в data/spell_overrides.json.
    7. Изменения применяются при следующем создании заклинания этого типа.

---

### 10. Настройки игры

*   **Основной поток:**
    1. Пользователь выбирает "Настройки" в главном меню.
    2. Система переходит в состояние 'settings'.
    3. Пользователь выбирает разрешение экрана из списка доступных (800x600, 1024x768, 1280x720, 1366x768, 1600x900, 1920x1080).
    4. Пользователь включает/выключает полноэкранный режим.
    5. Пользователь настраивает громкость звука и музыки.
    6. Система сохраняет настройки в data/settings.json.
    7. Система применяет изменения немедленно или при следующем запуске.

---

### 11. Просмотр информации о юните

*   **Основной поток:**
    1. Пользователь зажимает правую кнопку мыши на юните.
    2. Система отображает тултип с базовой информацией о юните (имя, здоровье, команда).
    3. Пользователь отпускает кнопку - тултип скрывается.
*   **Альтернативный поток (Двойной клик):**
    1. Пользователь дважды кликает правой кнопкой мыши на юните.
    2. Система открывает окно детальной информации (unit_info_window_open = True).
    3. Система отображает полную информацию: все характеристики, активные эффекты, способности.
    4. Пользователь закрывает окно кликом вне его или нажатием ESC.

---

### 12. Режим отладки

*   **Основной поток:**
    1. Пользователь нажимает F1 во время игры.
    2. Система переключает режим отладки (DEBUG_MODE).
    3. Система отображает дополнительную информацию: координаты юнитов, дальность хода, дальность атаки, инициативу.
*   **Дополнительные функции отладки:**
    1. F2 - Отладка дальности хода (подсветка доступных клеток для перемещения).
    2. F3 - Отладка дальности атаки (подсветка доступных целей для атаки).
    3. F4 - Отладка элементов интерфейса (границы кнопок, зоны клика).
    4. F5 - Отладка дальнобойных атак (визуализация дальности стрелков).
    5. F6 - Тестирование логики атаки (вывод информации о расчете урона).

---

### 13. Игра против ИИ

*   **Основной поток:**
    1. Пользователь настраивает бой, где одна из команд управляется ИИ (AIController).
    2. Когда наступает ход команды ИИ (selected_unit.team == ai_team):
    3. Система вызывает метод AIController для принятия решения.
    4. ИИ анализирует позиции союзников и врагов.
    5. ИИ выбирает оптимальное действие: перемещение, атака, применение заклинания или защита.
    6. Система автоматически выполняет выбранное действие.
    7. Система переходит к следующему ходу.
*   **Альтернативный поток (Режим наблюдателя):**
    1. Если обе команды управляются ИИ (spectator_mode = True):
    2. Пользователь наблюдает за боем без возможности вмешательства.
    3. Система автоматически обрабатывает все ходы.

---

### 14. Обработка событий и анимаций

*   **Основной поток:**
    1. Система обновляет состояние игры каждый кадр (метод update()).
    2. Система обрабатывает события Pygame (события мыши, клавиатуры).
    3. Система обновляет анимации юнитов (смена состояний: Idle, Walk, Attack, Hurt, Death).
    4. Система обновляет анимации заклинаний (полет снарядов, взрывы, эффекты).
    5. Система обновляет таймеры перезарядки заклинаний.
    6. Система отрисовывает кадр (метод draw()).
    7. Система обновляет экран (pygame.display.flip()).

---

### 15. Сохранение и загрузка настроек

*   **Основной поток:**
    1. Система автоматически загружает настройки из data/settings.json при запуске.
    2. При изменении настроек система сохраняет их в data/settings.json.
    3. Система загружает переопределения юнитов из data/unit_overrides.json.
    4. Система загружает переопределения заклинаний из data/spell_overrides.json.
    5. Если файлы не существуют, система использует значения по умолчанию из кода.
